# Expanded Analytics — Multiple Pages with Date Filtering

## Context

The existing Analytics page (`/superman/analytics`) has gateway cost widgets but no date filtering and limited scope. The user wants **separate analytics pages**, each focused on a different data domain, with period/date filtering.

Filament v5 Dashboard supports filter forms via `HasFiltersForm` trait. Widgets receive filter state via `InteractsWithPageFilters` trait (`$this->pageFilters`).

---

## Architecture: 3 Analytics Pages

Each page is a standalone Filament Dashboard page under the `Analytics` nav group, with its own `HasFiltersForm` date filter.

| Page | Route | Focus |
|------|-------|-------|
| **Cost & Profit** | `/superman/analytics/cost-profit` | Gateway costs, operator costs, margins, profit trends |
| **Messaging** | `/superman/analytics/messaging` | Delivery rates, failure reasons, DLR, volumes, source |
| **Financial** | `/superman/analytics/financial` | Deposits, transactions, spending, balances |

---

## Step 1: Shared Date Filter Trait

**New file**: `app/Filament/Concerns/HasDateFilter.php`

Trait that provides:
- `dateFilterForm(Schema $schema)` — Select (today/yesterday/this_week/last_7_days/this_month/last_30_days/this_year/custom) + DatePicker from/to for custom
- `resolveDateRange(?array $filters): array` — static helper returning `[Carbon $from, Carbon $to]`

All 3 analytics pages `use HasDateFilter` and call `$this->dateFilterForm($schema)` in their `filtersForm()`.

All widgets on these pages `use InteractsWithPageFilters` and call `HasDateFilter::resolveDateRange($this->pageFilters)`.
