# InfoZillion MNO Carrier Routing

## Problem

When the InfoZillion gateway uses `api_type=mno`, it can only send SMS to the same carrier (GP credentials -> GP numbers only). Currently, all messages in a batch go through one gateway with no carrier filtering, so MNO-type gateways could attempt cross-carrier delivery which the API won't accept.

## Approach

Infer the gateway's MNO from the `bill_msisdn` prefix. During batch processing, filter out recipients whose carrier doesn't match the gateway's MNO. Non-matching recipients are recorded in the failed report as "Carrier mismatch". When `api_type=iptsp`, no filtering is applied.

## Files to Create

### 1. `app/Support/MnoCarrier.php` (new)

Utility class that provides:
- `fromBillMsisdn(string $billMsisdn): ?string` - Returns MNO code (GP/BL/TT/RB) from bill_msisdn prefix
- `getOperatorPrefixes(string $mnoCode): array` - Returns operator prefix codes for the MNO (e.g., GP -> [13, 17])
- `matchesCarrier(string $e164Phone, string $mnoCode): bool` - Checks if a phone number belongs to the given MNO

Mapping:
```
bill_msisdn prefix -> MNO code -> operator codes
88013/88017        -> GP      -> [13, 17]
88014/88019        -> BL      -> [14, 19]
88015              -> TT      -> [15]
88016/88018        -> RB      -> [16, 18]
```

### 2. `tests/Unit/MnoCarrierTest.php` (new)

Unit tests for the MnoCarrier helper.

## Files to Modify

### 3. `app/Jobs/ProcessBatchJob.php`

**In `initialiseBilling()`** (around line 753):
- Load the gateway credentials
- If `api_type === 'mno'`, call `MnoCarrier::fromBillMsisdn()` to determine the gateway's MNO code
- Store as `$this->gatewayMnoCode` (new property)

**Add new property:**
```php
private ?string $gatewayMnoCode = null;
```

**In the recipient loop** (after phone validation at line 130, before body variable check at line 148):
- If `$this->gatewayMnoCode !== null`, check `MnoCarrier::matchesCarrier($formattedNumber, $this->gatewayMnoCode)`
- If no match, call `$this->recordFailure()` with reason "Carrier mismatch: recipient belongs to a different operator than the gateway" and continue

### 4. `tests/Feature/ProcessMessageBatchJobTest.php`

Add test cases:
- **MNO gateway filters non-matching carriers**: Create an InfoZillion MNO gateway with GP bill_msisdn, send batch with GP + BL numbers -> GP messages created, BL recorded as failed
- **MNO gateway accepts matching carriers**: Create gateway with GP bill_msisdn, send batch with only GP numbers -> all created
- **IPTSP gateway has no filtering**: Create IPTSP gateway, send batch with mixed carriers -> all created
- **Unknown bill_msisdn prefix has no filtering**: Gateway with unrecognized prefix -> all created (graceful degradation)
