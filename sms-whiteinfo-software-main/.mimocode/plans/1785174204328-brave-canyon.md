## Achievable with Current Data

### 1. Enhanced Message Statistics Widget
**Current**: Messages Today, Delivery Rate, Failed Today, Cost Today  
**Add**: Processing, DLR Received, DLR Pending

- `Processing` = messages WHERE status = 'sending'
- `DLR Received` = messages WHERE delivered_at IS NOT NULL
- `DLR Pending` = messages WHERE sent_at IS NOT NULL AND delivered_at IS NULL AND status != 'failed'

**File**: `app/Filament/Admin/Widgets/MessageStatsWidget.php`

### 2. Operator Traffic Analytics (New Widget)
Group messages by operator using phone prefix matching.

**Implementation**:
- Load operators with their codes (JSON array of prefixes)
- Match `messages.to` against operator codes
- Count messages per operator
- Display as Doughnut chart (similar to GatewayPerformanceChart)

**New File**: `app/Filament/Admin/Widgets/OperatorTrafficChart.php`

### 3. Failed Reason Summary (New Widget)
Aggregate `messages.failed_reason` field.

**Implementation**:
- Query messages WHERE status = 'failed' AND failed_reason IS NOT NULL
- Group by failed_reason, count occurrences
- Display as horizontal bar chart or table

**New File**: `app/Filament/Admin/Widgets/FailedReasonWidget.php`

### 4. DLR Summary (New Widget)
Delivery status breakdown.

**Implementation**:
- Count messages by status: pending, sending, sent, delivered, failed
- Display as Doughnut chart

**New File**: `app/Filament/Admin/Widgets/DlrSummaryChart.php`

### 5. Top Operators Widget (New Widget)
Similar to TopCustomersWidget but grouped by operator.

**New File**: `app/Filament/Admin/Widgets/TopOperatorsWidget.php`

### 6. Profit Calculation System
**Challenge**: Need to join messages with operators via phone prefix matching to get buying rates.

**Rate Model**:
- `operators.masking_price` / `non_masking_price` = buying rate (what Sendora pays)
- `messages.rate` = selling rate charged to customer
- `messages.cost` = rate * parts (total charge)
- **Profit** = messages.cost - (operator_buying_rate * messages.parts)

**Implementation Approach**:
Create a `ProfitCalculationService` that:
1. Loads all operators with codes into memory
2. For each message, matches phone to operator
3. Calculates buying cost using operator's masking/non_masking price
4. Aggregates by time period

**Optimization**: Cache aggregated profit data with 5-minute TTL using Laravel's cache system. Operator data loaded once per request.

**New Files**:
- `app/Services/Analytics/ProfitCalculationService.php`
- `app/Filament/Admin/Widgets/ProfitStatsWidget.php`
- `app/Filament/Admin/Widgets/ProfitTrendChart.php`

### 7. Fix Admin Export
Add `ExportAction` to Admin MessagesTable (already exists on Customer side).

**File**: `app/Filament/Admin/Resources/Messaging/Messages/Tables/MessagesTable.php`

## NOT Achievable Without New Features

These requirements need new infrastructure:

| Requirement | Reason |
|-------------|--------|
| Gateway Queue | Needs real-time queue monitoring |
| Gateway Response Time | Needs HTTP response time logging |
| SMS/Second, SMS/Minute throughput | Needs real-time rate calculation |
| Server Uptime | Already exists via Horizon |
| Gateway Error Logs | Needs new error logging table |
| API Error Logs | Needs new error logging table |
| Live Alerts | Needs notification system |
| Employee Access Permission | Needs new permission system |
| Export with Profit columns | Depends on profit calculation |
