# Plan: Dynamic Gateway Dashboard View

## Goal

Make the Filament Gateway View page display driver-specific information dynamically. Each SMS driver defines what data it exposes (balances, stats, etc.) and the View page renders it automatically — no hardcoded UI per gateway.

## Architecture

Follow the existing capability-detection pattern: new contract → driver implements → View page checks and renders.

```
SupportsDashboard (contract)
    ↓ implemented by
InfozillionDriver (returns DashboardData with multiple balance cards)
    ↓ checked by
ViewGateway (fetches data, renders via custom Blade view)
```

Rendering approach: `Filament\Schemas\Components\View::make()` with a custom Blade template (same pattern as `sms-stats.blade.php` in the existing codebase). Filament v5 has no `StatsOverview` infolist component — only `StatsOverviewWidget` (which is a page widget, not embeddable in a schema).

## Files to Modify

### 6. `app/Services/Sms/Drivers/InfozillionDriver.php`

- Add `implements SupportsDashboard`
- Add `getDashboardData(): DashboardData` — fetches wallet + per-MNO balances
- Add `fetchBalance(string $endpoint, array $payload): ?string` private helper
- Extend `resolveEndpoint()` with two new cases

**Balance fetch logic:**
```php
public function getDashboardData(): DashboardData
{
    $cards = [];

    // Wallet balance (CP-level)
    $wallet = $this->fetchBalance('check-current-balance', [
        'apiKey' => $this->credentials['api_key'] ?? '',
    ]);
    $cards[] = new StatCard(
        label: 'Wallet Balance',
        value: $wallet ?? 'N/A',
        description: 'Available balance at CP end',
        color: $wallet !== null ? 'success' : 'danger',
        icon: 'heroicon-o-banknotes',
    );

    // Per-MNO balances
    foreach (['GP' => 'GrameenPhone', 'RB' => 'Robi', 'TT' => 'Teletalk', 'BL' => 'Banglalink'] as $code => $name) {
        $balance = $this->fetchBalance('check-credit-balance', [
            'username' => $this->credentials['username'] ?? '',
            'password' => $this->credentials['password'] ?? '',
            'mno' => $code,
            'apiKey' => $this->credentials['api_key'] ?? '',
        ]);
        $cards[] = new StatCard(
            label: "{$name} Balance",
            value: $balance ?? 'N/A',
            description: "{$code} carrier credit",
            icon: 'heroicon-o-device-phone-mobile',
        );
    }

    return new DashboardData(cards: $cards);
}

private function fetchBalance(string $endpoint, array $payload): ?string
{
    try {
        $response = $this->client()->post($this->resolveEndpoint($endpoint), $payload);
        $data = $response->json() ?? [];

        if ($response->failed() || ($data['serverResponseCode'] ?? '') !== self::A2P_SUCCESS_CODE) {
            return null;
        }

        return $data['availableBalance'] ?? null;
    } catch (ConnectionException) {
        return null;
    }
}
```

**resolveEndpoint additions:**
```php
'check-credit-balance' => $type === 'iptsp'
    ? 'a2p-proxy-api-iptsp/api/v1/check-credit-balance'
    : 'a2p-proxy-api/api/v1/check-credit-balance',
'check-current-balance' => 'a2p-wallet/api/v1/check-current-balance',
```

### 7. `app/Filament/Admin/Resources/Settings/Gateways/Pages/ViewGateway.php`

Override `content()` to conditionally inject dashboard section above the infolist:

```php
use App\Contracts\SupportsDashboard;
use App\Services\Sms\Data\StatCard;
use App\Support\Facades\Sms;
use Filament\Schemas\Components\Section;
use Filament\Schemas\Components\View;
use Filament\Schemas\Schema;

class ViewGateway extends ViewRecord
{
    // ...

    public function content(Schema $schema): Schema
    {
        $components = [];

        $dashboardSection = $this->buildDashboardSection();
        if ($dashboardSection !== null) {
            $components[] = $dashboardSection;
        }

        $components[] = $this->getInfolistContentComponent();
        $components[] = $this->getRelationManagersContentComponent();

        return $schema->components($components);
    }

    private function buildDashboardSection(): ?Section
    {
        $gateway = $this->getRecord();
        $driver = Sms::usingGateway($gateway)->driver($gateway->driver->value);

        if (! $driver instanceof SupportsDashboard) {
            return null;
        }

        try {
            $dashboardData = $driver->getDashboardData();
        } catch (\Throwable) {
            return null;
        }

        if (empty($dashboardData->cards)) {
            return null;
        }

        return Section::make('Gateway Dashboard')
            ->schema([
                View::make('filament.admin.gateway-dashboard')
                    ->columnSpanFull()
                    ->viewData(['cards' => $dashboardData->cards]),
            ]);
    }
}
```

### 8. `app/Filament/Admin/Resources/Settings/Gateways/Schemas/GatewayInfolist.php`

No changes needed. Dashboard section is injected by ViewGateway above the infolist.

## Data Flow

```
1. Admin opens /superman/settings/gateways/{id}
2. ViewGateway::content() called
3. Gateway model loaded → driver resolved via Sms facade
4. If driver implements SupportsDashboard:
   a. getDashboardData() called
   b. InfozillionDriver hits wallet + MNO APIs in parallel-ish (sequential HTTP calls)
   c. Returns DashboardData with StatCard[] (wallet, GP, RB, TT, BL)
5. ViewGateway wraps cards in Section → View::make() Blade template
6. Blade renders responsive stat card grid
7. Below: existing infolist (name, driver, RPM, enabled, etc.)
```

## Future Extensibility

- **Other gateways**: Implement `SupportsDashboard`, return their own `DashboardData`. View page renders automatically.
- **DashboardSection**: Allows custom sections beyond stat cards (e.g., usage tables, config summaries).
- **Caching**: Add `Cache::remember("gateway:{$id}:dashboard", 60, ...)` in `getDashboardData()` or the page.
- **Auto-refresh**: Add `->polling('60s')` on the View page or the Section for live updates.
